01 / START LOCALLY

本地启动，连接真实 Agent

GitHub Pages 提供浏览器中的合成数据演示、历史浏览和回放。真实任务在本地 Node 服务中运行；Pages 页面本身没有 HTTP 后端，也不会调用你的 Codex 账户。 

git clone git@github.com:Jiayi-Liao/multi-agent-platform.git
cd multi-agent-platform
npm ci --ignore-scripts
npm start
# Dashboard & API: http://localhost:4310

需要 Node.js 22.13 或更新版本。确定性演示不需要 API key；真实模型演示需安装并登录 Codex CLI，用 ENABLE_CODEX=1 npm start 开启。

当前运行时源码仓库为私有，克隆和启动服务需要仓库访问权限。公开展示页可以直接浏览样例、回放，并下载 JavaScript client 模块。

接口的当前开放范围

HTTP API 只监听 127.0.0.1。适用于本机 Agent、脚本和运行时适配器；目前没有公网托管 API、账号系统或鉴权。Agent ID 是路由标识。浏览器写请求必须来自本地服务同源页面。

02 / HTTP CONTRACT

当前可用的 HTTP 接口

Base URL：http://localhost:4310。下表中 R = /api/runs/:runId；POST 使用 Content-Type: application/json，单次请求体上限 128,000 bytes。

方法与路径 用途 / 请求字段
GET /api/config 查看是否启用 Codex：{ enableCodex }。
GET /api/runs 列出任务，包含状态、Agent 数和事件数。
POST /api/runs 创建任务：{ title, mode? }。默认 custom；创建后返回 run，包括 id。
GET R 读取任务与有序历史事件：{ run, events }。
POST R/agents 注册任意角色：{ id?, name, role, parentId? }。父 Agent 必须已存在于当前任务。
POST R/messages 发送消息或回复：{ fromAgentId, toAgentId, content, id?, conversationId?, replyTo?, kind?, expectsResponse? }。
GET R/agents/:agentId/inbox 读取未处理收件箱。?limit=25，范围 1–100；按最早消息优先。
POST R/messages/:messageId/ack 由接收方确认：{ actorId, state }。
POST R/events 上报状态、工具与产物：{ type, payload }；支持的事件见下节。
GET R/stream SSE 实时事件。?after=:seq 补发历史；重连支持 Last-Event-ID。
POST R/finish 结束任务：{ status?, error? }。状态为 completed（默认）、failed 或 cancelled。若要中断平台拥有的演示进程，使用 cancel。
POST R/cancel 取消任务，并中断平台拥有的演示进程：{}。外部 Agent 的进程需要其适配器自行停止。
GET R/export 下载 JSON：{ version: 1, run, events }。
POST /api/demo 启动重写 / 验证演示：{ mode: "deterministic" | "codex" }；默认确定性模式，Codex 需显式启用。

常见错误返回 { error: "..." }：400 参数错误，403 同源或确认方不符，404 对象不存在，409 状态 / 幂等冲突，413 请求体过大，415 Content-Type 错误，429 同时运行的演示超过 3 个。

03 / MAILBOX & CORRELATION

从一个任务消息开始

curl -X POST http://localhost:4310/api/runs \
  -H 'Content-Type: application/json' \
  -d '{"title":"Research review"}'

# 用返回的 id 替换 RUN_ID，并先注册 planner 与 researcher。
curl -X POST http://localhost:4310/api/runs/RUN_ID/messages \
  -H 'Content-Type: application/json' \
  -d '{"id":"request-1","conversationId":"review-1",
       "fromAgentId":"planner","toAgentId":"researcher",
       "content":"Find relevant papers.","expectsResponse":true}'
queued→delivered→processing→answered

接收方用 ACK 标记 delivered、processing；failed 为终止状态。需要回复的请求（expectsResponse=true，默认值）必须用同一 conversationId、原消息 replyTo 且发送 / 接收方对调的新消息回答，系统会自动将原请求标记 answered。无需回复的消息可由接收方 ACK answered。

kind 支持 chat、task_request、task_result、feedback、error。消息内容上限 32,000 字符；ID 和 conversationId 上限 100 字符。

重试时复用显式 id 和 conversationId：相同内容幂等返回，冲突内容返回 409。一个 conversation 只属于同一任务中的两个参与者。成功完成任务前必须处理完待回复请求与正在运行的工具；结束后任务只读。

04 / OBSERVABILITY

Agent 状态、工具与产物

事件类型 payload
agent.status { agentId, status, activity? }
idle / working / waiting / completed / failed
tool.started { id, agentId, name, input? }
tool.completed { id, agentId, output?, error? }
工具必须由当前 Agent 启动且仍在运行。
artifact.created { agentId, name, content, id?, version? }
版本为正整数；content 上限 32,000 字符。

消息和任务生命周期事件由服务生成。runtime.activity 由内置 CLI 适配器内部记录，当前没有开放通过 HTTP 任意写入该类型。

05 / JAVASCRIPT CLIENT

用九个方法连接自己的 Agent

项目提供 PlatformClient：createRun、register、send、reply、inbox、ack、status、record、finish。它是一个源码模块，目前没有单独发布 npm 包。下载 client.js ↓ 

import { PlatformClient } from './src/client.js';

const planner = new PlatformClient({ agentId: 'planner' });
const run = await planner.createRun('Research review');
await planner.register({ name: 'Planner', role: 'planning' });
const researcher = new PlatformClient({ runId: run.id, agentId: 'researcher' });
await researcher.register({ name: 'Researcher', role: 'research', parentId: 'planner' });

const request = await planner.send('researcher', 'Find relevant papers.', {
  id: 'request-1', conversationId: 'review-1'
});
// 外部 worker 用 researcher.inbox() 轮询待处理消息。
await researcher.ack(request.id, 'delivered');
await researcher.ack(request.id, 'processing');
await researcher.status('working', 'Reviewing papers');
// 在这里调用你自己的 Agent 运行时。
const result = await researcher.reply(request, 'Here is the research summary.');
await planner.ack(result.id, 'delivered');
await planner.ack(result.id, 'answered');
await researcher.record('artifact.created', {
  name: 'Research brief', content: 'The research summary.', version: 1
});
await planner.finish();

任何运行时都可使用 HTTP 接入。当前没有 MCP 服务，也不会自动截获任意 Codex Desktop 对话或原生子 Agent 消息；通信需经此 broker 或由适配器上报。

06 / LIVE EVENTS & REPLAY

实时订阅，保留完整历史

curl -N 'http://localhost:4310/api/runs/RUN_ID/stream?after=0'

# SSE 每条事件：
# id: 42
# data: {"seq":42,"id":"...","runId":"...",
#        "type":"message.sent","timestamp":...,"payload":{...}}

事件的 seq 是数据库中的全局有序游标；ID 与 timestamp 同时保留。重连传入最后看到的 seq 即可补发。UI 使用相同事件投影重建任意历史时刻，回放不会重新执行模型或工具。
