01 / START LOCALLY

Run locally. Connect real agents.

GitHub Pages provides synthetic browser demos, history browsing, and replay. Real tasks run on your local Node server. The Pages site has no HTTP backend and does not use your Codex account. 

git clone https://github.com/Jiayi-Liao/multi-agent-platform.git
cd multi-agent-platform
npm ci --ignore-scripts
npm start
# Dashboard & API: http://localhost:4310

Requires Node.js 22.13 or newer. The deterministic demo needs no API key. For the real model demo, install and sign in to Codex CLI, then start with ENABLE_CODEX=1 npm start.

The source repository is public, so anyone can clone it and start the local server. The demo site lets you browse samples, replay runs, and download the JavaScript client module.

Current API access

The HTTP API listens only on 127.0.0.1 for local agents, scripts, and runtime adapters. There is currently no hosted public API, account system, or authentication. Agent IDs are routing identifiers. Browser write requests must come from the same origin as the local server.

02 / HTTP CONTRACT

Available HTTP endpoints

Base URL: http://localhost:4310. In this table, R = /api/runs/:runId. POST requests require Content-Type: application/json and a request body of at most 128,000 bytes.

Method & path Purpose / request fields
GET /api/config Check whether Codex is enabled: { enableCodex }.
GET /api/runs List runs with their status, agent count, and event count.
POST /api/runs Create a run: { title, mode? }. The default mode is custom. Returns the run, including its id.
GET R Read a run and its ordered event history: { run, events }.
POST R/agents Register any role: { id?, name, role, parentId? }. The parent agent must already exist in this run.
POST R/messages Send a message or reply: { fromAgentId, toAgentId, content, id?, conversationId?, replyTo?, kind?, expectsResponse? }.
GET R/agents/:agentId/inbox Read outstanding messages, oldest first. Use ?limit=25; the allowed range is 1–100.
POST R/messages/:messageId/ack Acknowledge as the recipient: { actorId, state }.
POST R/events Record status, tools, and artifacts: { type, payload }. Supported event types are listed below.
GET R/stream Stream live events over SSE. ?after=:seq replays missed events; reconnects also support Last-Event-ID.
POST R/finish Finish a run: { status?, error? }. Status can be completed (default), failed, or cancelled. Use cancel to interrupt a platform-owned demo process.
POST R/cancel Cancel a run and interrupt platform-owned demo processes: {}. External agent processes must be stopped by their own adapters.
GET R/export Download JSON: { version: 1, run, events }.
POST /api/demo Launch the rewriter/verifier demo: { mode: "deterministic" | "codex" }. Defaults to deterministic mode; Codex must be explicitly enabled.

Errors return { error: "..." }: 400 invalid input; 403 origin or acknowledgment actor mismatch; 404 object not found; 409 state or idempotency conflict; 413 request body too large; 415 unsupported Content-Type; 429 more than three demos running concurrently.

03 / MAILBOX & CORRELATION

Start with a task message

curl -X POST http://localhost:4310/api/runs \
  -H 'Content-Type: application/json' \
  -d '{"title":"Research review"}'

# Replace RUN_ID with the returned id; register planner and researcher first.
curl -X POST http://localhost:4310/api/runs/RUN_ID/messages \
  -H 'Content-Type: application/json' \
  -d '{"id":"request-1","conversationId":"review-1",
       "fromAgentId":"planner","toAgentId":"researcher",
       "content":"Find relevant papers.","expectsResponse":true}'
queued→delivered→ processing→answered

The recipient acknowledges delivered and processing. failed is terminal. Requests that expect a reply (expectsResponse=true, the default) require a new message with the same conversationId, the original message ID as replyTo, and the sender and recipient reversed. The server automatically marks the original request answered. Messages that do not expect a reply can be acknowledged as answered by the recipient.

kind supports chat, task_request, task_result, feedback, and error. Message content is limited to 32,000 characters; IDs and conversation IDs are limited to 100 characters.

Reuse explicit id and conversationId values when retrying. Identical messages are idempotent; conflicting content returns 409. A conversation belongs to two participants within a single run. Resolve all outstanding replies and running tools before completing a run successfully. Finished runs are read-only.

04 / OBSERVABILITY

Agent status, tools, and artifacts

Event type Payload
agent.status { agentId, status, activity? }
idle / working / waiting / completed / failed
tool.started { id, agentId, name, input? }
tool.completed { id, agentId, output?, error? }
The tool must have been started by this agent and still be running.
artifact.created { agentId, name, content, id?, version? }
Versions are positive integers; content is limited to 32,000 characters.

The server generates message and run lifecycle events. The built-in CLI adapter records runtime.activity internally; this type cannot currently be written through the public HTTP API.

05 / JAVASCRIPT CLIENT

Connect your agents with nine methods

The project provides PlatformClient: createRun, register, send, reply, inbox, ack, status, record, and finish. It is a source module, currently not a separate npm package. Download client.js ↓ 

import { PlatformClient } from './src/client.js';

const planner = new PlatformClient({ agentId: 'planner' });
const run = await planner.createRun('Research review');
await planner.register({ name: 'Planner', role: 'planning' });
const researcher = new PlatformClient({ runId: run.id, agentId: 'researcher' });
await researcher.register({ name: 'Researcher', role: 'research', parentId: 'planner' });

const request = await planner.send('researcher', 'Find relevant papers.', {
  id: 'request-1', conversationId: 'review-1'
});
// External workers poll researcher.inbox() for outstanding messages.
await researcher.ack(request.id, 'delivered');
await researcher.ack(request.id, 'processing');
await researcher.status('working', 'Reviewing papers');
// Call your own agent runtime here.
const result = await researcher.reply(request, 'Here is the research summary.');
await planner.ack(result.id, 'delivered');
await planner.ack(result.id, 'answered');
await researcher.record('artifact.created', {
  name: 'Research brief', content: 'The research summary.', version: 1
});
await planner.finish();

Any runtime can connect over HTTP. There is currently no MCP server or automatic capture of arbitrary Codex Desktop conversations or native subagent messages. Route communication through this broker or report events through an adapter.

06 / LIVE EVENTS & REPLAY

Subscribe live. Keep the full history.

curl -N 'http://localhost:4310/api/runs/RUN_ID/stream?after=0'

# Each SSE event:
# id: 42
# data: {"seq":42,"id":"...","runId":"...",
#        "type":"message.sent","timestamp":...,"payload":{...}}

Each event's seq is a globally ordered database cursor; event IDs and timestamps are also retained. Reconnect with the last seen sequence to receive missed events. The UI uses the same event projection to reconstruct any point in history. Replay does not rerun models or tools.
